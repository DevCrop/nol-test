# 2026-10-27 추가 적용 순서

- 고객 계정 정보 확정 전에는 운영 배포를 보류합니다. 운영 파일·DB의 최신 백업과 복원 절차를 먼저 확보합니다.
- 이미 기존 보안 스키마가 적용된 DB: 점검/유지보수 시간에 sql/manual/bluesquare-temporary-password-20261021.sql → sql/manual/admin-transactions-20261027.sql → sql/manual/account-authority-20261027.sql 순서로 실행합니다. 덤프 전체 복원이나 과거 계정 이메일 SQL을 다시 실행하지 않습니다.
- 구형 운영 DB: 기존 release/preflight.sql 및 적용 대상 검토 → 기존 보안 증분 changes.sql → 위 추가 SQL 세 개 순서로 복사 DB에서 먼저 검증합니다. 이미 적용한 보안 변경을 맹목적으로 재적용하지 않습니다.
- InnoDB 전환은 테이블 잠금과 추가 디스크 공간이 필요할 수 있습니다. 운영 중 ALTER 실행을 피하고 원본과 행 수·계정 값 보존을 확인합니다. MyISAM으로 자동 역전환하는 down SQL은 제공하지 않습니다.
- 추가 SQL을 두 번 실행해 재실행 안전성을 확인하고 deploy/preflight.php schema 및 실제 계정/권한/임시 비밀번호 QA를 통과한 뒤 같은 후보의 웹 파일을 배포합니다.
- 기존 .env·고객 업로드·운영 콘텐츠를 보존합니다. SQL/가이드/QA는 공개 웹 루트에 올리지 않습니다.
- 실제 고객 이메일·권한·허용 IP를 반영하고 MFA 수신 및 SSL/HTTP 운영 정책은 별도로 확인합니다. 이전 날짜 가이드와 충돌하면 이번 추가 적용 요구를 먼저 충족합니다.
- 계정·권한 관리 요청은 2~300자 변경 사유를 필수로 받습니다. 유효기간은 한국 시간으로 시작 포함/종료 제외이며 빈 경계는 제한 없음입니다. 기존 계정은 NULL 경계를 유지합니다. 유효기간 변경은 로그인 토큰을 폐기하며 진행 중 MFA는 권한 버전 불일치로 거부됩니다.
- 생성·수정·삭제·재발급·잠금 해제의 성공 이력에는 작업자 ID/IP/시각, 대상 계정 번호·소유자 식별, 변경 사유와 변경 전후 권한/기간을 남깁니다. 이력 저장 실패 시 해당 계정 변경을 롤백합니다. 비밀번호·OTP·세션 토큰은 이력에 넣지 않습니다.
- 10월 27일 v1 로컬 후보는 권한 상세 기능 추가 전 검사용입니다. 최신 상세 기능은 v2 이후 후보로 검증해야 합니다. 고객 계정 정보가 오기 전 생성하는 후보는 운영 최종본이 아닙니다.

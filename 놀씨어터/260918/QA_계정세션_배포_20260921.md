## 이번 변경

- 원본 260918.sql을 보존하고 프로젝트별 sql/release에 변경 SQL, 사전 검사, 구조 스냅샷, SHA-256 명세를 분리했다. 실제 계정 행이나 SMTP 비밀은 포함하지 않았다.
- 원본 nb_admin DDL을 가진 임시 DB에서 부분 적용 후 재개/두 번 실행/원본 계정 값 보존/잘못된 프로젝트·컬럼 타입 중단을 검증했다. 사용자 Docker DB 볼륨을 초기화하지 않았다.
- 블루 비밀번호 검증을 놀의 8자 이상·4개 문자군 중 3개 기준에 맞췄고, 양쪽에서 bcrypt의 72바이트 초과 입력을 거부한다. 블루 입력 UI도 일치시켰다.
- 블루 요청마다 비밀번호 변경 필요·활성 계정·로그인 토큰을 재검사한다. 강제 변경 중 관리 화면 접근을 차단한다.
- 블루 로그인/MFA CSRF, MFA 코드 형식, 만료·재발송 예산, 인증 도중 비밀번호/이메일/계정 상태 변경을 확인한다.
- 관리자 HTML이 인증보다 먼저 나오던 블루 32개 페이지를 수정했다. AJAX 인증 오류에 HTML이 섞이던 문제를 실제 HTTP 검사로 재현·수정했다.
- 세션 쿠키: strict mode, only cookies, host-only, HttpOnly, SameSite=Lax, 운영 Secure.
- 두 프로젝트에 동일한 SessionIdleTimer 모듈을 복제해 독립 배포를 유지한다. 코드 SHA-256이 일치한다. DB 모델·인증 경로는 각 프로젝트 기존 구조를 유지한다.
- 타이머 GET 조회는 시간을 연장하지 않는다. POST 활동은 서버 응답 후 갱신한다. 다른 탭 활동은 15초 폴링으로 반영한다. 통신 실패 시 임의 연장하지 않는다.
- 블루 일반 관리자/최고관리자 계정 관리와 놀의 메뉴별 ACL은 동일한 데이터 모델이 아니다. 이번 변경이 메뉴별 세부 ACL까지 동일하게 이식한 것은 아니다.

## 남은 운영 확인

확정 도메인/DNS/인증서, 호스팅의 실제 DocumentRoot/Alias 설정, 프로젝트별 발신 메일·앱 비밀번호, 관리자 수신 메일, 허용 IP/CIDR/프록시, 운영 CORS, TLS 대상 ARN 확인이 필요하다.
실 SMTP 송수신 및 실서버 최신 DB 사본의 배포 리허설은 아직 하지 않았다. 운영배포.md 절차를 따른다.
SQL의 DDL은 자동 커밋이므로 백업 없이 실행하지 않는다. 사전 검사는 컬럼 타입·NULL 등 정의된 조건을 확인하며 모든 인덱스·트리거 차이를 자동 해결하지 않는다.
